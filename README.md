# Этап 1. Минимальный прототип с конфигурацией

## Цель этапа

Разработка минимального CLI-приложения для визуализации графа зависимостей Maven-пакетов с возможностью настройки параметров через командную строку.

На данном этапе реализован прототип приложения, который принимает параметры запуска, проверяет их корректность и выводит конфигурацию в формате ключ-значение.

## Структура проекта

```text
dependency-visualizer/
│
├── src/
│   ├── main.py
│   └── dependency_visualizer/
│       ├── __init__.py
│       └── cli.py
│
├── tests/
│   └── test_cli.py
│
├── README.md
├── .gitignore
├── pyproject.toml
└── run.bat
```

## Настраиваемые параметры

Для настройки приложения используются аргументы командной строки.

| Параметр | Описание | Пример |
|---|---|---|
| `--package` | Имя Maven-пакета в формате GROUP:ARTIFACT | `org.slf4j:slf4j-api` |
| `--repository` | URL репозитория или путь к тестовому файлу | `https://repo.maven.apache.org/maven2` |
| `--test-mode` | Включение тестового режима | `--test-mode` |
| `--version` | Версия анализируемого пакета | `2.0.16` |
| `--output` | Имя выходного PNG-файла | `dependencies.png` |
| `--ascii-tree` | Включение режима ASCII-дерева | `--ascii-tree` |
| `--max-depth` | Максимальная глубина анализа зависимостей | `5` |

## Проверка параметров

Для обработки аргументов командной строки используется стандартная библиотека Python `argparse`.

Реализованы следующие проверки:

- Имя пакета должно соответствовать формату GROUP:ARTIFACT.
- Версия пакета должна содержать допустимые символы.
- URL репозитория должен иметь схему HTTP или HTTPS.
- В тестовом режиме указанный файл должен существовать.
- Имя выходного файла должно иметь расширение `.png`.
- Каталог для сохранения выходного файла должен существовать.
- Максимальная глубина должна быть целым неотрицательным числом.
- Имя выходного файла не может быть пустым.

При обнаружении некорректного параметра программа выводит сообщение об ошибке и завершает выполнение.

## Пример запуска

```bash
python src/main.py \
    --package org.slf4j:slf4j-api \
    --repository https://repo.maven.apache.org/maven2 \
    --version 2.0.16 \
    --output dependencies.png \
    --ascii-tree \
    --max-depth 5
```

## Пример вывода

```text
Параметры запуска:
package = org.slf4j:slf4j-api
repository = https://repo.maven.apache.org/maven2
test_mode = False
version = 2.0.16
output = dependencies.png
ascii_tree = True
max_depth = 5
```

## Примеры обработки ошибок

Некорректное имя пакета:

```bash
python src/main.py --package invalid-package \
    --repository https://repo.maven.apache.org/maven2 \
    --version 1.0
```

Некорректный URL репозитория:

```bash
python src/main.py --package org.example:library \
    --repository invalid-url \
    --version 1.0
```

Отрицательная максимальная глубина:

```bash
python src/main.py --package org.example:library \
    --repository https://repo.maven.apache.org/maven2 \
    --version 1.0 \
    --max-depth -1
```

Во всех случаях программа сообщает об ошибке и завершает работу.

## Тестирование

Для проверки корректности работы CLI реализованы автоматические тесты с использованием стандартной библиотеки `unittest`.

Проверяются:

- корректная конфигурация реального репозитория;
- корректная конфигурация тестового режима;
- некорректное имя пакета;
- некорректный URL репозитория;
- отсутствие тестового файла;
- некорректная версия пакета;
- неправильное расширение выходного файла;
- отрицательная максимальная глубина.

Запуск тестов:

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

Для Windows также предусмотрен запуск через файл `run.bat`.

Для получения информации используется Maven Repository.

Программа самостоятельно загружает POM-файлы
и анализирует их XML-содержимое.

## Используемые библиотеки

Используются стандартные библиотеки Python:

- urllib.request — HTTP-запросы;
- xml.etree.ElementTree — обработка XML;
- re — обработка свойств Maven;
- dataclasses — представление зависимостей.

Сторонние библиотеки и менеджеры пакетов
для получения зависимостей не используются.

## Реализованные возможности

- Формирование URL POM-файла.
- Загрузка POM из Maven-репозитория.
- Извлечение прямых зависимостей.
- Получение groupId, artifactId и version.
- Получение scope и optional.
- Подстановка свойств Maven.
- Получение зависимостей из родительского POM.
- Использование dependencyManagement для определения версий.
- Обработка ошибок загрузки и разбора XML.
- Вывод прямых зависимостей в консоль.

## Запуск

Пример:

--repository https://repo.maven.apache.org/maven2 \
--version 2.0.16

# Этап 3. Основные операции над графом зависимостей

## Цель этапа

Реализация построения графа зависимостей Maven-пакетов
с учетом транзитивных зависимостей.

Для обхода графа используется алгоритм BFS
с рекурсивной обработкой очереди.

## Структура проекта

```text
conf-upr-graph-var18/
│
├── src/
│   ├── main.py
│   │
│   └── dependency_visualizer/
│       ├── __init__.py
│       ├── cli.py
│       ├── maven.py
│       ├── test_repository.py
│       └── graph.py
│
├── tests/
│   ├── test_cli.py
│   ├── test_maven.py
│   ├── test_test_repository.py
│   └── test_graph.py
│
├── test_repository.json
│
├── README.md
├── .gitignore
├── pyproject.toml
└── run.bat
```

## Реализованные возможности

- Построение графа зависимостей.
- Получение транзитивных зависимостей.
- Ограничение глубины анализа.
- Обработка циклических зависимостей.
- Обработка повторяющихся зависимостей.
- Работа с локальным тестовым репозиторием.
- Проверка корректности JSON-файла.

## Алгоритм BFS

Для построения графа используется поиск в ширину
(Breadth-First Search).

Алгоритм использует очередь для хранения вершин,
ожидающих обработки.

Для предотвращения повторной обработки вершин
используется множество visited.

Обработка очереди реализована рекурсивно.

## Ограничение глубины

Максимальная глубина задается параметром:
```
--max-depth N
```
Глубина корневого пакета равна 0.

При глубине 0 анализируются только корневые вершины.

При глубине 1 получаются прямые зависимости.

При глубине 2 дополнительно получаются зависимости
первого уровня зависимостей.

## Тестовый репозиторий

В тестовом режиме используется JSON-файл.

Пример:
```text
{
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["E"],
    "D": ["F"],
    "E": ["F"],
    "F": []
}
```
Пакеты обозначаются заглавными латинскими буквами.

Запуск:
```text
python src/main.py --package A \
--repository test_repository.json \
--test-mode \
--version 1.0 \
--max-depth 5
```
## Обработка циклических зависимостей

Для обнаружения повторно встречающихся вершин
используется множество visited.

Если вершина уже посещалась, она не добавляется
повторно в очередь.

При этом соответствующее ребро сохраняется в графе.

Таким образом, циклические зависимости не приводят
к бесконечному обходу.

## Тестирование

Для проверки реализованы автоматические тесты:

- построение обычного графа;
- ограничение глубины 0, 1 и 2;
- циклические зависимости;
- общие зависимости;
- отсутствие зависимостей;
- некорректная глубина;
- загрузка тестового репозитория;
- некорректный JSON;
- некорректные имена пакетов.

Запуск:
```
python src/main.py --package A --repository test_repository.json --test-mode --version 1.0 --max-depth 10
```

с использованием алгоритма BFS и рекурсии.

Поддерживается анализ транзитивных зависимостей,

Также реализован режим работы с локальным
